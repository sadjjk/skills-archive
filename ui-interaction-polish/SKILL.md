# 交互质感 Skill

让界面在被操作时清楚地回应。先把反馈做好，再考虑装饰。

## 1. 先读页面，接着实现

先查看目标页面、相关组件、样式、交互逻辑和项目约定，识别：

- 技术栈、组件库、已有 token 与动效能力。
- 用户指定的改动范围、需要保留的功能。
- 可操作元素及其悬停、按下、焦点、加载、禁用、错误状态。
- 哪些 transform、阴影、伪元素和事件处理器已经被占用。
- 页面能否本地运行、仓库已有的检查命令和浏览器工具。

用一两句说明观察到的问题及要改的范围，然后直接修改。信息能从代码推断就继续；只有无法判断的关键业务行为才需要提问。

用户没有指定范围时，优先处理主操作、表单和折叠面板；检查整页可操作元素，但不要因此给所有卡片装上特效。

## 2. 冲突时的优先级

用户明确要求 > 原有业务功能与可用性 > 品牌和组件库规范 > 本 Skill 的默认参数。

默认只改交互：

- 保留布局、文案、配色、字体、图片、路由、链接和业务数据。
- 保留表单校验、提交请求、加载与禁用状态、分析事件和组件对外接口。
- 原页面静止时没有的高光和阴影，只在交互状态出现；静止状态保持原样。
- 不新增视差、数字滚动、背景粒子、常驻发光、自动收起导航或新依赖。
- 不自动删除原有动画；若它干扰操作，做最小范围调整并在交付里说明。

静止截图对比时固定视口、缩放、主题、字体、滚动位置和数据，等待原有入场结束。记录动态内容造成的差异，不把它算成改版成果。没有逐像素比较就不要声称“零像素变化”。

## 3. 五个设计思路

### 3.1 反馈要快，出现可以慢

交互反馈和入场动画分开配置。以下是起点，已有设计系统有明确要求时沿用它：

| 场景 | 默认时长 |
|---|---|
| 按下进入 | 80–100ms |
| 悬停进入 | 150–200ms |
| 松开、移出 | 200–300ms |
| 折叠展开、短内容出现 | 200–350ms |
| 已有整段入场 | 保留原方案；必要时可更长 |

- 反馈曲线可用 `cubic-bezier(0.2, 0, 0, 1)`。
- 不新增 `transition: all`；修改范围内已有的 `all` 改为实际需要的属性。
- 明确列出变化属性；不要顺便给 width、padding、font-size 加动画。
- hover、active、focus 切换要连续。快速进出、连点、展开中反向操作时不能跳回起点。
- CSS 声明的时长不等于实测延迟；交付时区分两者。

### 3.2 按下有重量

- 实心主按钮可轻微下沉约 1px，并把阴影收短。
- 小型次操作可缩到约 0.97；大面积的折叠行可用约 0.99，或仅改变背景。
- 悬停需要抬起时控制在 1–2px；默认不靠放大制造注意力。
- 文本链接优先使用颜色或下划线，不必套按钮的下沉效果。
- 输入框重点是聚焦、输入、错误反馈，不给输入文字的区域做按压缩放。
- 不覆盖原有居中、拖动、展开、轮播的 transform。能安全组合时使用独立 translate/scale；否则调整现有状态层，不盲目套全局规则。

### 3.3 光影来自同一个方向

默认光从上方来。先用项目的阴影 token；没有时，从下面的层次关系开始：

- 顶部内高光：深底约白色 18%，浅底约白色 70%。
- 贴地影：小、近，例如 `0 1px 2px rgb(0 0 0 / 12%)`。
- 环境影：大、淡，例如 `0 8px 24px -8px rgb(0 0 0 / 18%)`。

全页用少量层级即可。悬停抬高时环境影扩大、变淡；按下时收小。配合背景调整透明度，避免黑底上无效的黑影。

以上效果只在适合的组件和交互状态出现，遵守“静止不变”。不要为了展示光影把原有扁平风格改成拟物风格。

### 3.4 跟手，但按需使用

跟随光是可选增强：只在较大的卡片或主展示区域中、确实有助于表达当前操作对象时使用。普通列表、密集后台和文本区通常不需要。

- 深底用很淡的白光，浅底用很淡的品牌色；从低透明度开始。
- 可用 `radial-gradient(240px circle at var(--x) var(--y), <光色>, transparent 60%)`。
- 坐标来自指针位置减去当前卡片的边界；离开时淡出。
- 用组件已有装饰层，或确认未被占用的伪元素。装饰层设 `pointer-events: none`，不能盖住文本、焦点环或点击区域。
- 仅在 `(hover: hover) and (pointer: fine)` 且未开启减少动态效果时启用。按输入能力判断，不按设备名称或屏幕宽度猜。
- 不让每次 pointermove 触发全组件渲染；需要时合并到每帧一次更新。卸载组件或媒体条件变化时清理监听和待执行的帧。

### 3.5 一次只强调当前操作

- 悬停只突出当前元素，不让整组一起发光或移动。
- 不新增常驻动画。已有动画同时争夺注意力时，优先保留表达状态所需的那一个。
- 加载、错误、成功等状态的清晰度高于装饰。
- 必要信息不能靠 hover 才出现；触控和键盘必须能完成同样的任务。

## 4. 把状态补全

优先沿用语义化控件、框架和组件库机制：

- **键盘焦点**：使用 `:focus-visible`，默认约 2px 外环、2px 偏移，确保背景上可见且未被裁切。不能只删 outline。
- **按钮**：hover、active、focus-visible、disabled、loading 都要检查；禁用时不播放可点击的反馈，提交期间不重复触发。
- **输入框**：保留标签、输入值、光标、校验逻辑和错误关联；聚焦边框或外环可以更明确，错误同时有文字提示。
- **折叠面板**：优先保留原生 details/summary 或现有组件，不破坏 aria-expanded、键盘操作、焦点与隐藏语义。内容高度变化、快速反向操作都应正常。
- **普通展示卡片**：不因装饰而添加 role=button、tabindex 或点击行为；不要制造它可以点击的错觉。
- **减少动态效果**：在 `prefers-reduced-motion: reduce` 下关闭新增位移、缩放、跟随光和滚动动效，保留即时的颜色、轮廓和状态提示。仍需看得出“我操作到了”。

## 5. 实现约束

- 样式限定到目标组件，避免覆盖全站 `button`、`a`、`input`。
- 先复用现有 token、事件和状态，不复制一套互相竞争的逻辑。
- 不在 render 期间添加全局监听；清理订阅、动画和观察器。
- 聚焦、按下与展开不要改变控件尺寸或引起布局跳动。
- 不为动画拦截正常链接、表单、指针、键盘或焦点行为。
- 不编造用户数、评价、授权、性能提升或测试结论。

## 6. 验证后交付

按 [验证清单](references/verification.md) 检查本次改动，使用项目已有命令和可用浏览器工具。

先静态检查，再实际运行：检查桌面鼠标、键盘、触控与减少动态效果；对比改前改后静止状态，确认原功能可用。验证范围随改动规模决定，不为简单样式调整搭建整套测试基础设施。

浏览器不可用时，继续完成可做的修改和静态检查，明确列出尚未验证项。不要把“代码看起来正确”写成“实测通过”，不要把修改前的案例数字当作当前项目结果。

交付简洁说明：改了哪些反馈、为何这样改、实际检查了什么、还有什么没验证。优先给出可以直接查看的页面或对照图。
