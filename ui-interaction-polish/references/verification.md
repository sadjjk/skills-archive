# 交互质感验证清单

只报告实际做过的检查。不是所有项目都有浏览器和测试工具；缺少工具就注明。

## 改之前

- 记录本次目标组件及不可改变的业务行为。
- 能运行时，记录启动方式、目标路由、视口、主题、缩放、滚动位置和数据状态，并保存静止截图。
- 等待字体、图片和已有入场加载完成。动态内容单独标记，避免把时间变化算成修改造成的差异。

## 静态检查

- 没有新增依赖、背景动画、视差或数字滚动。
- 目标范围内不使用 transition: all；过渡只包括实际变化属性。
- 没覆盖组件原有 transform、伪元素或事件处理。
- 没有把静态展示卡片伪装成可点击控件。
- pointermove 不引起全组件每次重渲染；监听与帧任务可清理。
- loading、disabled、错误和减少动态效果有对应处理。
- 使用仓库适用的格式、类型、构建或已有测试命令；不要虚报未执行的命令。

## 桌面鼠标

- 进入、离开、按下、松开、按住后移出，都有合理状态。
- 快速进出、连续点击不会卡住、闪烁或跳回动画起点。
- 主按钮按下反馈清楚；没有因过渡所有属性造成的尺寸变化。
- 如果有跟随光：坐标正确，离开后消失，内容仍清晰，不能挡住点击。
- 链接仍去原地址；表单仍走原有提交逻辑。真实提交有副作用时使用本地测试数据或已有测试方式，不触发真实交易或发送。

## 键盘

- Tab / Shift+Tab 顺序正常，每个可操作元素的焦点都可见。
- 按原生控件语义检查 Enter / Space，而不是强迫所有控件使用同一种按键。
- 折叠面板状态与可见内容一致；隐藏内容不成为意外的 Tab 停靠点。
- 焦点环未被 overflow、装饰层或阴影遮住。

## 触控与减少动态效果

- 在无 hover 的触控配置下验证：必要信息不依赖鼠标，控件能正常点开和关闭。
- 不能只缩窄视口就声称完成触控验证。浏览器模拟与真机测试分开记录。
- 开启 prefers-reduced-motion: reduce 后，新增位移、缩放和跟随光关闭，但焦点、颜色和状态提示仍可见。

## 静止对比

- 与改前使用相同条件，鼠标放到非目标空白区域，处理好焦点与展开状态。
- 查看文字、布局、间距、尺寸、图像、颜色是否意外变化。
- 使用图像差异工具时说明阈值、动态区域处理和环境差异。只有实际比较过才报告具体像素数字。
- 伪元素和内部子元素也可能负责反馈。只比较元素自身 computed style 不能证明它“完全没有反馈”。

## 交付模板

- 改动：具体组件、状态、反馈节奏。
- 依据：为什么有助于当前操作。
- 已验证：实际命令、运行环境、交互场景及结果。
- 未验证：缺少工具或受环境限制的项目。
- 剩余问题：真实观察到的问题；没有证据就不写“全部通过”。
